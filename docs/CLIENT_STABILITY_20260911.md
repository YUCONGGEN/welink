# 客户端 0.1.2-preview · 2026-09-11

本次处理用户实机反馈：安卓顶部标题覆盖状态栏，会议底部按钮被导航栏遮挡；Windows 启动后整窗黑屏，托盘使用通用图标。增加通话和会议麦克风实际输入音量波动。上一版 0.1.1 的头像资源递归安装修复保留；用户随后提供的截图已能进入消息和原生会议页。

## 修复

Android 的主页面、会议 / 通话和扫码页面统一使用 `ScreenInsets`。从窗口获取当前状态栏、导航栏、显示切口与键盘的 inset，给原生内容容器留出空间，再将已消费的 inset 停止向 WebView 重复传递；顶部额外留 6 dp，底部留 8 dp。不依赖写死某款手机的状态栏高度，旋转和键盘变化时重新应用。

Windows 黑屏现场检查显示：主 HWND 可见，但 `Chrome_WidgetWin_0` 及其后代全部不可见。旧代码只对主窗口调用 `ShowWindow`，DOM 脚本仍能运行，所以先前的 DOM 成功回调不能证明画面已显示。现将 WebView2 控制器的 `PutIsVisible` 显式接入启动、托盘隐藏和恢复，并在显示时更新 bounds。为此保留一份带 MIT 许可证的 `go-webview2` 小补丁副本，具体差异见 `third_party/go-webview2/WELINK_PATCHES.md`。

PE 资源实际的 `RT_GROUP_ICON` 编号为 2，编号 1 属于清单。窗口和托盘统一加载 2；测试拒绝通用程序图标。

音量波动来自实际音频幅度。Android 在现有 WebRTC 音频设备的 PCM 回调中计算 RMS，Windows 页面用已有麦克风轨道连接 analyser；两端按约 100 ms 更新最近 7 个采样柱，静音归零，结束时释放监测资源。不会为显示波动另开一个麦克风、保存录音或向扬声器回放。

## 验证

- Windows 隐藏启动器测试同时检查 DOM 就绪和实际 Chromium 子窗口可见，已通过。
- 原生托盘生命周期、自定义图标、显示 / 隐藏 / 恢复、重复启动唤回、聊天，以及隐藏主窗口后的会议邀请通过。
- 麦克风浏览器测试使用真实 AudioContext 音频：幅度变大、静音、衰减、关闭、重复关闭，以及保留通话所持有轨道；Java PCM 测试覆盖静音、正负幅度、满幅与不完整采样。
- Android lint、构建、APK v2 签名、16 KB 对齐、119 个 UI 资源、4 ABI 与资源递归安装回归通过。版本码 3，保留原签名，可覆盖安装。
- 本地 P2P、TURN UDP、TURN TCP 三条实际音视频路径最终完整通过。第一次强制 TCP 检查在接通前超时，复测相同客户端通过；原因未确认，保留为间歇性问题，不能据此承诺所有网络零故障。失败时现保存 ICE / RTP 状态用于排查。
- 测试客户端移到本地 18749，避开用户已安装客户端使用的 18746；仍只使用本地测试账号和 18246 API。

Android 0.1.2 的系统栏 / 键盘布局、原生音量波动尚未完成真机验收。此前软件模拟器未完成系统框架启动，不能代替这项验收。
