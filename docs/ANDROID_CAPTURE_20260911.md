# Android 0.1.5-preview · 麦克风采集与会议资源释放

本次只更新 Android 客户端，版本码 6。Windows 保持 0.1.4-preview，服务端保持 `welink-server-release-20260911-03`。

## 修复

之前创建 WebRTC 音轨后只等待库的录音回调；独自进入会议、尚未建立发送连接时，没有主动请求采集。现在启用麦克风时调用当前会议 AudioDeviceModule 的 `requestStartRecording()`，复用同一个录音器。`MicrophoneInput` 只计算回调中真实 PCM 的 RMS，不创建第二个录音器，不使用随机或模拟波形。

静音及主持人静音立即清空音量；重新开启时等待新采样，不复用静音前的音量。过期采样逐步衰减至零。采集失败会禁用麦克风、显示重试提示；再次开启前重新检查权限。退出时先释放客户端的采集请求，再关闭媒体连接和工厂，迟到的采样不能重新启动音量条。

会议初始化中途失败也执行资源释放；相机开启失败立即释放已创建的采集器、纹理和视频源，便于再次尝试。清理单项资源失败时继续释放其余资源，并恢复原音频模式。录音检查任务使用会议持有的调度器，退出时关闭。Activity 销毁会直接释放媒体；离开确认框不再访问可能已被远端结束事件清空的会议对象。WebRTC 初始化失败后允许再次初始化。

文件保存复用 Activity 持有并在销毁时关闭的执行器，修复每次下载遗留一个常驻线程的问题。

## 证据与限制

- 对打包使用的 `webrtc-local.aar` 检查 `javap` 接口与字节码：主动采集和原生发送分别持有录音请求；`requestStopRecording()` 释放客户端请求，原生连接仍需要录音时继续保留同一个录音器。没有原生发送时，PCM 回调仍会执行。AAR SHA-256 为 `0a1627b1a48c2bc17d9a40d62fc47bd45166f44a311e95917f147c402de379b0`。
- `sh scripts/android-microphone-test.sh` 通过。测试覆盖 PCM 有符号幅度、静音和溢出边界；无参会连接时请求采集、幂等启动、未收到 PCM 不产生波形、采样过期、静音和退出后的迟到回调、失败清理与重试，以及停止录音等待采样线程时的锁顺序。设备行为通过测试替身注入，这不是安卓硬件录音测试。
- Android lint、构建、v2 签名和 16 KB 对齐检查通过。最终构建耗时 44 秒。
- 最终 APK 的 119 个当前 UI 文件、4 个原生 ABI、100 个嵌套头像、安装升级及中断后重试检查通过。
- 当前未连接安卓设备。独自入会时的真实麦克风采集、其他成员加入后的音频连续性、反复切换与退出后的系统录音状态、不同厂商的触摸边距仍待真机验收。不能据此声称没有崩溃或完整 QQ 功能等价。
