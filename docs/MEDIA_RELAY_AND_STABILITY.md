# 媒体连接与稳定性 · 2026-09-11

通话和会议采用与 YuDesk 相同的直连优先思路。每次进入媒体房间取得当前登录会话的 RTC 配置：第一阶段只使用 STUN；默认 8 秒未连接，或连接明确失败时，加入带短期凭证的 TURN UDP / TCP 地址并重启 ICE。连接后根据实际选中的候选对显示“P2P 直连”或“中转连接”。中转阶段仍可选择恢复可用的直连路径。

## 服务与端口

生产配置在 `/Users/yu/bin/welink/welink.json`，`media.enabled: true`，Go 服务内运行 Pion TURN。Windows、Android 使用同一份服务端配置，Android 在原生 WebRTC 控制器中执行回退。

| 配置 / 端口 | 当前值或行为 |
|---|---|
| HTTP API / 下载 | TCP 8250 / 8251 |
| STUN / TURN | UDP / TCP 8252；STUN 使用 UDP |
| UDP 中转端口 | 20000–20127，共 128 个 |
| 直连等待 | `media.direct_timeout_ms: 8000` |
| 中转凭证 | 默认 6 小时，绑定用户及登录会话 |
| 每用户分配上限 | 32，全部设备合计 |
| 每用户中转速率 | 4 MiB/s，上下行合计 |
| 会议规模 | mesh，默认 8 人、120 分钟；没有 SFU |

`GET /api/rtc-config` 必须登录；共享密钥只保存在服务器 `media-secret`，权限 0600，不发送给客户端。退出、改密、管理员重置密码或删除账号会使对应中转连接失效。默认不允许向私网、回环和共享地址段转发；本地测试才通过 `allowed_peer_cidrs` 显式放行。两端都使用同一台 TURN 时，服务内部处理本机中转路由，避免依赖路由器公网地址回环。

媒体在直连和中转时均保持 WebRTC DTLS/SRTP 加密。按照部署要求，信令、登录和聊天仍走 HTTP / WebSocket；TURN TCP 不等同于 HTTPS 或 TURN TLS。

## 路由器映射

`scripts/upnpc-media-refresh.py` 读取配置，先列出现有映射，只维护明确标为 `WeLink-media` 的端口；其他服务占用相同端口时拒绝覆盖。当前已通过 SSH 执行，建立上述 130 条永久映射，公网 UDP / TCP 分配和双向数据通过。

Mac 的 `cn.welink.media-ports` 登录域任务每 300 秒尝试刷新，但当前后台运行访问网关出现 `No route to host`；同一脚本从 SSH 运行可访问。尚未解决这一后台网络访问差异，不能称为自动刷新已验收。现有映射 lease 为 0，路由器清空映射后需手动执行：

```sh
python3 ~/bin/welink/upnpc-media-refresh.py
```

任务记录在 `logs/media-ports.log` 和 `logs/media-ports-error.log`。原有 `~/bin/frp/upnpc-refresh.sh` 及其他端口映射保留。

## 本次稳定性修复

- 挂断后立即重拨先等上一通电话结束状态同步，防止界面已关闭但客户端仍判定忙线。
- 摄像头授权晚于会议结束返回时，立即停止刚获得的采集轨道；离开的房间不能被迟到的回调重新启动。
- Android SDP 回调统一回到主线程，并检查连接所属房间与协商版本，忽略已关闭连接的过期回调。
- Android 结束通话、成员离开和停止屏幕共享时先解除显示绑定，再释放视频轨道 / 连接；切换摄像头完成和失败回调回到主线程并检查页面生命周期。
- Android 0.1.1-preview 修复截图中的“启动失败 ui/avatars”：资源安装器递归处理子目录，原子替换文件，失败时清理临时文件并允许重试。启动按钮防止重复提交，Activity 销毁后不再打开旧页面。
- Windows 保留原生托盘图标；关闭后驻留、恢复、重复启动唤回、未读计数、托盘重新注册，以及主窗口隐藏时的会议邀请经过原生测试。

## 验证与限制

本版本服务端完整 56 项测试通过（72 秒）；TURN 的鉴权、实际 UDP 传输、配额、注销失效和同机 UDP / TCP 中转路由专项 race 测试通过。浏览器实际收发合成音视频，三条路径分别验证 P2P、强制 TURN UDP、强制 TURN TCP，持续接收音频字节和视频帧并检查挂断释放。另通过完整通话、三人会议、迟到摄像头授权、挂断重拨回归。
