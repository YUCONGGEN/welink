# 本机草稿与持久发送 · 2026-09-11

后续需求取消聊天附件的 50 MB 大小上限。默认不超过 50 MB 的附件仍进入本机持久队列；超过该阈值或本机 Blob 保存失败时直接流式上传，需保持客户端运行。100 条 / 250 MB 只是可配置的本机待发送队列限制，不是聊天或网盘容量限制。网盘配额独立为每账号 5 GB。

Windows 和 Android 共用的界面将文字、@成员范围和引用编号保存在本机；引用正文不复制进草稿，重新打开聊天时按当前权限恢复。原消息已撤回或不可访问时会取消引用。网络暂时不可用时仍保留引用编号，避免恢复前发送而丢掉引用。

文字、图片、文件、语音和视频先存入 IndexedDB，再清空输入框并开始发送。队列元数据与附件 Blob 分开存储，不会因渲染聊天而加载全部待发送文件。每个服务器和账号最多保留 100 条、合计 250 MB 待发送内容，单文件沿用 50 MB 限制。保存失败时文字留在输入框；录音或视频会提示当前窗口内重试保存，不能声称保存失败的内容已经持久化。

草稿携带版本标识，入队事务只清除本次发送对应的版本。快速切换聊天并输入新内容时，旧入队操作不会删除新草稿；异步视频读取和重试也核对服务器、账号及登录会话，避免登录状态变化后发送旧选择。

隔离范围为规范化服务器地址、服务器指纹和账号 ID，切换其他服务器或账号不会显示或发送原账号的内容。退出登录立即停止发送工作和当前请求，清空界面；原范围的草稿和待发送内容仍保留，重新登录同一服务器、同一账号后恢复。清除应用数据或卸载会丢失本机内容；它们不跨设备同步。

每个会话依次发送，前一条延迟或失败会阻止该会话后续消息。普通网络错误按 2–30 秒间隔重试，限流后等待一分钟；登录过期停止，权限或参数等明确错误显示失败原因。用户可在消息旁重试或移除，也可通过“设置 → 本机待发送消息”处理已退出或解散会话的残留内容。移除只删除本机副本；已经送达的消息仍需在聊天记录中撤回。

每条队列记录的消息标识在重启、重试中保持不变。重试先向 `GET /api/outbox/{clientId}` 核对送达结果；该接口只返回本账号发送记录的编号和会话编号，不恢复撤回、个人删除或已失去权限的消息正文。确认送达后移除队列记录与本机附件。上传也使用同一个稳定标识，服务端在 `upload_requests` 保存账号、标识、附件编号和内容指纹；相同内容重传返回原附件，不生成重复附件或遗留临时文件；标识用于不同内容时返回 409。

服务端对上传的实际字节、文件名、会话、媒体类型及校验后的元数据计算指纹；在事务中再次检查当前发言权限，避免大文件上传过程中退群、禁言或好友关系变化后仍写入附件。旧客户端省略上传标识时继续使用原流程。已上传但尚未生成消息的服务端附件沿用现有存储策略，本轮未增加附件自动清理或断点续传。

服务端离线时，冷启动保留本机登录状态并显示重新连接，可手动重试或等待自动重试；恢复认证后加载草稿和发送队列。当前没有已收聊天记录的完整离线缓存，冷启动仍需连接服务端后进入聊天。Android 后台存活和系统推送不属于此队列保证；应用再次启动后才继续工作。

`scripts/outbox-test.mjs` 使用本地私有测试账号验证浏览器进程关闭 / 重启、断网冷启动、文字及四类附件依次恢复、UTF-16 @范围与引用、账号隔离、相同账号 ID 的服务器范围隔离、上传和消息成功但响应丢失、撤回 / 删除后的送达核对、恢复时禁言检查、移除与本机 Blob 清理。手机截图和触摸测试来自 Chromium 手机视口，不能替代 Android 真机验收。

兼容性检查禁用 `AbortController`、`Object.fromEntries` 和 `Array.flatMap` 后运行上述流程；这只验证相应接口缺失时的行为，不代表完整旧版 WebView 验收。无法真正中断 fetch 的旧环境会停止后续发送步骤；原请求若稍后在服务端提交，下一次重试通过送达核对清理。

Go 新增测试覆盖并发重复上传、内容 / 名称 / 会话 / 媒体类型冲突、账号隔离、上传文件与数据库无额外副本、好友关系失效、送达凭据在撤回 / 删除 / 退群后的行为及鉴权。语音视频、@提醒、消息操作 / 设备安全和转发的浏览器回归通过；待发送气泡与实际送达气泡分别校验。

完整服务端 Go race 测试通过，耗时 502.342 秒；初次 300 秒总时限不足，保持原有密码哈希成本，将测试时限调整为 900 秒后完成。Windows 原生测试关闭原窗口，再由另一测试进程使用相同 WebView 用户目录和本地地址恢复登录、草稿及待发送消息，验证服务端只有一份消息；测试继续覆盖托盘、未读和重复启动。原生测试使用私有临时服务器，不向线上服务注册测试账号。
