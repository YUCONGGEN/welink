# 联系人管理 · 2026-09-11

后续需求已改为全员直接聊天，取消好友申请前置条件。“删除”仅从最近列表移除，聊天历史、备注与分组保留；下次聊天恢复。搜索结果和资料页可直接发消息或拨打语音 / 视频。新增屏蔽私聊消息及取消屏蔽，保留历史和本人主动发送能力，共同群消息不受影响。黑名单仍独立生效，解除后无需重新申请。下面记录的是旧版关系模式实现；当前规则以 STORAGE_AND_SPACES.md 为准。

Windows / Android 的联系人列表支持自建好友分组、备注和私有描述，资料页与私聊标题显示个人备注。Windows 右键或 Android 长按好友打开操作菜单；好友资料和私聊设置也有入口。分组最多 50 个、名称 24 字，支持重命名、上移 / 下移、折叠 / 展开和删除。删除分组只移回默认“我的好友”，不删除好友或备注。分组折叠状态保存在当前设备，其余资料通过服务端同步。

备注最多 32 字、描述最多 200 字，仅本人查询的好友资料返回这些信息；对方和其他用户不会收到。服务端检查分组所属账号，跨账号分组引用、修改和排序均被拒绝。排序一次提交完整分组顺序，在事务中校验和更新；分组已变化时需刷新。

删除好友解除双方好友关系，保留原私聊与历史；新的私聊消息、附件上传、转发和单聊会议邀请被拒绝。共同群聊继续保留。重新添加好友后沿用原私聊，已有历史仍可访问。删除会清理关联的个人备注 / 分组 / 描述，再添加时不恢复旧备注。

拉黑同时解除好友关系、取消双方待处理好友申请、阻止新的申请和私聊。黑名单仅本人可见；解除拉黑不自动恢复好友，需重新申请。双方已经进行的远程协助和关联单聊会议会结束。在其余非群会议中（包括关联其他私聊的会议），若拉黑双方之一是发起人，则断开另一方入会连接，并阻止后续通过会议号重新加入；共同群会议仍按群成员权限处理。

“设置 → 联系人与隐私”提供允许搜索和接收好友申请开关。关闭搜索后陌生人不能按号码、别名、昵称搜索到本人，已有好友仍可搜索；在线状态也只向当前好友提供。关闭申请只影响新的好友申请，不撤销已有待处理申请。对方已经知道的账号资料和保留的会话不会被清除。

新增 `contact_groups`、`contact_preferences`、`contact_blocks`、`contact_privacy`。数据库触发器在私聊消息 / 远控写入、好友申请和关系写入时再次检查权限，覆盖检查后发生删除或拉黑的并发情况。远控隧道注册后再次核验状态，避免拉黑与建立连接交错时留下连接。客户端收到关系变更后关闭私聊输入区域，保留历史查看，并可进入联系人资料确认关系。

专项测试覆盖备注隔离、分组所有权、排序、删除分组、隐私开关与部分更新、删除 / 拉黑后的文字 / 转发 / 上传限制、保留共同群聊与历史、取消申请、解除后不自动恢复、重新添加沿用旧会话，以及远控双端隧道和关联会议关闭。测试中的响应对象每次独立解码，避免 Go 复用切片元素而残留 `omitempty` 字段造成错误判断。
