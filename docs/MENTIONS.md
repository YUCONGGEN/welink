# 群聊 @提醒 · 2026-09-11

Windows 与 Android 共用的聊天界面支持输入 `@` 搜索群成员，按群名片、昵称或 WeLink 号码筛选。Windows 可用方向键选择、Enter 确认、Esc 关闭；安卓可触摸选择。输入栏有 `@成员` 按钮，群消息右键 / 长按菜单提供 `@TA`。群主和管理员可选 `@全体成员`，普通成员只能选择具体成员。成员列表显示当前全部候选人，群规模上限沿用 200 人。

每处提醒保存具体账号和文字范围，每条文字消息最多 50 处。范围按 UTF-16 计算，兼容 WebView 输入框、emoji 和中文。选择时插入当前群名片或昵称；发送时在同一事务内检查当前成员资格、管理权限、文字范围、名称及发言权限，并同时保存消息和提醒对象。成员已退出或名称变化时拒绝发送，客户端重新取得成员资料供再次选择。普通输入的 `@昵称` 只作为文字，不产生账号提醒。

草稿切换聊天后保留提醒范围；在提醒前编辑文字会移动范围，改动提醒本身则取消该处账号绑定，避免通知错误的人。退出登录清空本地会话内的文字和提醒草稿。当前草稿仅保存在运行中的界面内存，不属于持久离线发送队列。

消息中 @文字显示为蓝色；群聊列表显示 `[有人@我]`，免打扰群也保留 @未读计数。首次进入未读群聊可通过“有人 @我 · 查看消息”定位第一条未读提醒，包括较早的消息。查看聊天记录可勾选“只看 @我的消息”，并与关键词、消息类型、发送人、日期筛选组合。已读沿用服务端序号，同账号设备同步；切到联系人等其他页面时，后台会话消息不会被误记为已读。

`@全体成员` 的收件人固定为发送当时的群成员，排除发送者；单人提醒也排除发送者。后续改名不会改变原文或绑定的账号。个人删除会移除本人未读提醒，撤回会清除展示和所有人的未读提醒；历史筛选不返回已撤回内容。逐条 / 合并转发保留文字副本，不重新 @转发目标群成员。共同群聊仍遵循既有群成员权限。

新增 `message_mentions` 和 `message_mention_recipients` 表。服务器统一消息查询返回提醒范围与实际收件人，客户端据此处理实时提醒，避免仅依据 `@全体成员` 的字面内容判断。消息 API 增加 `mentions=me` 筛选，按当前认证账号匹配；客户端无法指定别人的提醒收件箱。旧消息没有提醒记录，升级后继续正常读取。

当前系统通知依赖界面运行和系统通知授权；Android 系统推送、后台进程存活与真机键盘行为仍待验收。手机截图和触摸联调来自 Chromium 手机视口，不代表 Android 真机验收完成。
